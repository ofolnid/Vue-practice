# Vue 실습과제

## 1. Weather Mockup

### 1.1 기본 구현

- `v-for`를 통한 배열 렌더링으로 날씨 데이터를 반복 출력했다.
- `v-if` 조건부 렌더링으로 기온이 25도 이상이면 더움, 25도 미만이면 선선함 라벨이 렌더링되게 했다.
- 양방향 바인딩(단방향 바인딩 + 이벤트를 통한 갱신으로 양방향 구현, `:value`, `@input`)을 검색용 인풋에 구현해 검색 쿼리를 추적하고 화면에 표시하게 했다.
- 날씨 카드 선택 이벤트, 상세보기 클릭 이벤트를 구현했다.

### 1.2 추가 구현

- 기본 제공된 날씨 목업 데이터에 습도와 강수 확률 항목을 추가했다.
- 이를 토대로 불쾌 지수를 계산하여, `v-if`를 활용해 불쾌지수 정도에 따라 매우 불쾌/불쾌/보통 라벨이 렌더링 될 수 있도록 했다.

### 1.3 트러블 슈팅 & 배운 점

- 상세보기 클릭 이벤트(Alert 창)가 실행되지 않는 문제
  - 파라미터에서는 `city`, 내부 실행문에서는 `cityName`으로 작성해 변수명 불일치로 함수가 실행되지 않고 있었다.
  - 수정 후 정상 작동 확인

## 2. Weather Composition

### 2.1 기본 구현

- computed를 활용해 검색어 필터링 도시 목록인 `filteredWeatherList`를 계산했다.
- `watch`, `watchEffect`를 활용해 상태바 문구 변경과 검색어 변경을 추적하고 console에 출력하게 했다.
- 검색 결과에 따른 도시 리스트만 출력되게 변경하고, 검색어가 비었을 때는 원본 데이터 전체 출력, 검색어와 일치하는 데이터가 없을 경우 `v-if`를 활용해 일치하는 도시가 없음을 안내하는 요소가 출력되게 했다.

### 2.2 추가 구현

- `computed`를 활용해 전체 도시의 평균 기온, 검색 결과 개수를 계산했다.

### 2.3 트러블 슈팅 & 배운 점

- 선택적 렌더링
  - `v-if`와 `v-show`의 선택적 렌더링에 대해 학습하고, 렌더링 유무가 자주 변경되지 않고 해당 사용자에게 보이면 안되는 요소의 경우 `v-if`를 사용해야 함을 이해했다.
- `computed` 동작 원리
  - `computed`는 의존성이 있는 요소(추적하는 값)가 변경되지 않았을 경우 함수 재계산을 하지 않아 효율적임을 학습하고, 매번 재계산될 필요가 없는 값을 만드는 함수에 적용했다.

## 3. Weather Component

### 3.1 기본 구현

- 기능 변경 없이 기존 Weather Composition의 구현 내용을 4개의 Component 파일로 분리했다.
- `slot`을 활용해 검색박스, 리스트박스의 디자인을 공통화했다.
- `props`와 `emit`을 활용해 `WeatherParent`와 `WeatherCard`, `SearchBar` 사이의 데이터와 이벤트 전달을 구현했다.
- 각 컴포넌트에 한정된 디자인을 scoped style로 분리했다.

### 3.2 추가 구현

- `EmptyState` 컴포넌트를 추가 분리하여 결과가 없을 때 렌더링할 공통 컴포넌트를 생성했다.

### 3.3 트러블 슈팅 & 배운 점

- 부모-자식 사이 이벤트가 제대로 발생하지 않는 문제
  - `emit`을 통해 부모에게 전달할 때, `emit` 이름을 '' 따옴표 안에 작성하지 않아 존재하지 않는 함수라는 에러가 발생했다.
  - 수정 후 정상 작동 확인
- `slot`을 컴포넌트처럼 구성
  - 처음엔 `slot`의 역할을 공통 컴포넌트일 것이라고 잘못 이해하고 있어 내부에 title, content를 분리해 받으려고 했다.
  - 템플릿 또는 레이아웃 역할을 수행하는 것에 가깝다는 것을 이해하고(예를 들자면 모달 레이어 내부같은 역할) 수정했다.

## 4. Weather Router

### 4.1 기본 구현

- Vue Router를 설정하고 라우터 지연 로딩과 Catch-all Route(Not Found)를 적용했다.
- NavBar 컴포넌트를 분리 생성하고, `RouterView`와 함께 `App` 내에 배치했다.
- 홈, 어바웃 페이지를 생성하고 홈을 제외한 페이지에 메인 대시보드로 돌아가는 버튼을 추가했다.
- 디테일 페이지를 생성하고 동적 경로에 매칭되는 `cityId`의 데이터를 출력하도록 했다.
- 잘못된 경로로 진입할 경우를 캐치해 렌더링될 Not Found 페이지를 생성했다.

### 4.2 추가 구현

- 목업 데이터의 통계를 볼 수 있는 `WeatherStatistics` 페이지를 생성 및 구현했다.
- 페이지를 만들며 반복되는 코드를 컴포넌트화하여 분리했다. (`InfoRow`, `AboutCard`, `StatCard`)

### 4.3 트러블 슈팅 & 배운 점

- 공통 스타일 문제
  - 공통적으로 적용되어야 할 스타일(`box-sizing: border-box` 등)이 제대로 적용되지 않았다.
  - 상위 컴포넌트에서 적용한다고 하더라도 `scoped`라면 하위 컴포넌트에는 적용되지 않음을 확인했다.
  - `App`에서 `scoped`가 아닌 전역 스타일로 공통 스타일을 정의해 해결했다.

## 5. Weather Store

### 5.1 기본 구현

- 날씨 단위를 세팅하는 `configStore`을 생성 및 적용했다.
- `UnitToggler`를 생성하여 `NavBar`에 배치했다.

### 5.2 추가 구현

- `themeStore`를 생성하여 light, dark 테마에 따라 `App` 스타일이 변경되도록 했다.
- `themeToggler`를 생성해 `NavBar`에 배치했다.

### 5.3 트러블 슈팅 & 배운 점

- 화씨-섭씨 변환 함수
  - 여러 페이지에서 같은 온도 변환 함수를 각각 작성하면 코드가 중복될 수 있었다.
  - 온도 단위 상태를 `configStore`에서 관리하고 있어, 변환 함수도 함께 작성해 공통으로 사용하도록 했다.
  - 메인, 상세, 통계 페이지에서 같은 변환 함수를 재사용할 수 있었다.
- `theme` 관리
  - 각 페이지와 컴포넌트마다 `theme`에 따라 색상을 따로 지정하면 같은 스타일 코드가 반복될 수 있었다.
  - light / dark 테마의 색상 값을 전역 CSS 파일의 변수로 정의했다.
  - 각 컴포넌트에서는 `var(--color-...)` 형태로 해당 변수를 사용하도록 수정했다.

## 6. Weather Axios

### 6.1 기본 구현

- axios 라이브러리를 설치하고 OpenWeatherMap API를 활용해 실제 날씨 데이터로 교체했다.

### 6.2 추가 구현

- 홈과 통계 페이지에서 동일한 날씨 데이터를 사용할 수 있도록 API 통신과 날씨 데이터를 `weatherStore`에서 관리하게 했다.
- 상세 페이지에서는 선택한 도시의 데이터를 별도로 조회하여 체감 온도, 습도, 기압, 풍속, 가시거리, 일출/일몰 등의 상세 정보를 제공하도록 확장했다.
- OpenWeatherMap의 Air Pollution API를 추가로 사용해 상세 페이지에 대기질 정보를 매핑해 표시했다.
- 통계 페이지에 현재 날씨 상태별 도시 수를 확인할 수 있는 날씨 분포 기능을 추가했다.
- JSONPlaceholder API를 사용해 CRUD 예제 페이지를 생성하고, `GET`, `POST`, `PUT`, `DELETE` 기능을 구현했다.

### 6.3 트러블 슈팅 & 배운 점

- OpenWeatherMap 한국어 날씨 상태값 번역 이상 문제
  - 흐림을 온흐림 등으로 번역해 쉽게 알아볼 수 없는 문제가 있었다.
  - 날씨 상태값 코드를 자체적으로 매핑하고 변환하여 출력할 수 있도록 했다.
- API 응답 구조와 기존 데이터 구조 불일치
  - 기존에 만들어두었던 데이터 구조와 실제 API 구조가 일치하지 않아 수정이 필요했다.
  - 강우 확률은 제공하지 않아 제외하고, 그 외 제공하는 다른 정보를 API 요청 후 결과로 반환할 때 선택적으로 매핑하여 반환하여 해결했다.
- API 요청 전 빈 배열로 인한 계산 오류
  - 실제 날씨 데이터는 비동기로 받아오므로 초기 렌더링 시 `weatherList`가 빈 배열인 상태가 있었다.
  - 이때 평균 기온 계산에서 `0 / 0`이 되어 `NaN`이 발생할 수 있어, 데이터가 없을 경우 0을 반환하도록 했다.
- API 로딩 상태와 빈 데이터 상태가 동시에 표시되는 문제
  - API 요청 직후에 `weatherList`가 비어 있어 로딩 안내와 '검색 결과 없음' 안내가 동시에 출력되는 문제가 있었다.
  - `v-if / v-else-if / v-else`로 로딩, 에러, 빈 데이터, 정상 데이터 상태를 순서대로 분리해 하나의 상태만 렌더링되도록 수정했다.

## 7. Weather UI 라이브러리

### 7.1 기본 구현

- Element Plus 라이브러리를 설치하고 `skeleton`, `switch(토글)` 컴포넌트에 적용했다.

### 7.2 추가 구현

- CRUD 예제 페이지에 Element Plus 라이브러리를 활용하여 `el-table`, `el-input`, `el-button`, `el-dialog`, `ElMessage`, `ElMessageBox` 등을 적용해 목록 조회, 등록, 수정, 삭제 UI를 구현했다.

### 7.3 트러블 슈팅 & 배운 점

- 검색바 교체 문제
  - 기존 검색바를 `el-input`으로 교체한 후, 한글 입력시 검색어가 한 박자 늦게 갱신되는 문제가 발생했다.
  - 외부 UI 라이브러리를 사용하면 UI를 간단하게 구성할 수 있지만, UX 관점에서 오히려 불편함을 준다면 적용하지 않는 것이 맞다고 판단했다.
  - 따라서 검색바는 기존 구현을 유지하고 기존 기능을 해치지 않는 부분에만 Element Plus를 선택적으로 적용했다.
